PASO 7 — Registrar el backend como Servicio Windows
─────────────────────────────────────────────────────
  Usar NSSM (Non-Sucking Service Manager):
  Descargar gratis: https://nssm.cc/download (nssm-2.24.zip)
  Extraer nssm.exe a C:\Windows\System32\

  Desde CMD como Administrador:

    nssm install ApolloBackend "C:\ApolloSupport\backend\venv\Scripts\uvicorn.exe"
    nssm set ApolloBackend AppParameters "main:app --host 127.0.0.1 --port 8001 --workers 1"
    nssm set ApolloBackend AppDirectory "C:\ApolloSupport\backend"
    nssm set ApolloBackend AppEnvironmentExtra "PYTHONPATH=C:\ApolloSupport\backend"
    nssm set ApolloBackend DisplayName "Apollo Support Backend"
    nssm set ApolloBackend Description "FastAPI backend para ApolloSupport"
    nssm set ApolloBackend Start SERVICE_AUTO_START
    nssm set ApolloBackend AppStdout "C:\ApolloSupport\backend\logs\backend.log"
    nssm set ApolloBackend AppStderr "C:\ApolloSupport\backend\logs\backend_error.log"

    nssm start ApolloBackend

  Verificar:
    sc query ApolloBackend
    → Estado: RUNNING ✔

PASO 9 — Habilitar módulos de Apache necesarios
─────────────────────────────────────────────────
  Editar C:\Apache24\conf\httpd.conf y asegurarse que estén SIN comentario (#):

    LoadModule proxy_module modules/mod_proxy.so
    LoadModule proxy_http_module modules/mod_proxy_http.so
    LoadModule proxy_wstunnel_module modules/mod_proxy_wstunnel.so
    LoadModule rewrite_module modules/mod_rewrite.so
    LoadModule headers_module modules/mod_headers.so

  ⚠ Si alguna línea tiene # al inicio, quitarlo y guardar.


PASO 10 — Configurar Virtual Host en Apache
─────────────────────────────────────────────
  Editar o crear: C:\Apache24\conf\extra\httpd-vhosts.conf
  Agregar al final:

  ──────────────────────────────────────────────────────────────
  <VirtualHost *:80>
      ServerName support.ultimate.net.ar
      DocumentRoot "C:/Apache24/htdocs/apollosupport"

      # ── Frontend SPA: todas las rutas van a index.html ────────
      <Directory "C:/Apache24/htdocs/apollosupport">
          Options -Indexes +FollowSymLinks
          AllowOverride All
          Require all granted
          FallbackResource /index.html
      </Directory>

      # ── API: proxy al backend FastAPI ─────────────────────────
      ProxyPreserveHost On

      # WebSocket (PRIMERO, antes que el proxy HTTP genérico)
      RewriteEngine On
      RewriteCond %{HTTP:Upgrade} websocket [NC]
      RewriteCond %{HTTP:Connection} upgrade [NC]
      RewriteRule ^/api/(.*) ws://127.0.0.1:8001/api/$1 [P,L]

      # HTTP normal
      ProxyPass        /api  http://127.0.0.1:8001/api
      ProxyPassReverse /api  http://127.0.0.1:8001/api

      # ── Headers de seguridad ───────────────────────────────────
      Header always set X-Frame-Options "SAMEORIGIN"
      Header always set X-Content-Type-Options "nosniff"

      # ── Logs ──────────────────────────────────────────────────
      ErrorLog  "logs/apollosupport_error.log"
      CustomLog "logs/apollosupport_access.log" combined
  </VirtualHost>
  ──────────────────────────────────────────────────────────────

  Verificar que httpd.conf incluye este archivo:
    Include conf/extra/httpd-vhosts.conf


PASO 11 — Crear .htaccess en la carpeta del frontend (alternativa al FallbackResource)
────────────────────────────────────────────────────────────────────────────────────────
  Crear C:\Apache24\htdocs\apollosupport\.htaccess:

    Options -MultiViews
    RewriteEngine On
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteRule ^ /index.html [QSA,L]

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Backend no arranca:
    → Revisar C:\ApolloSupport\backend\logs\backend_error.log
    → Verificar que PostgreSQL acepta conexiones desde el servidor

  WebSocket falla (visor en negro):
    → Verificar que mod_proxy_wstunnel está activo en Apache
    → Revisar que la regla RewriteRule del WS está ANTES del ProxyPass

  Agente no aparece online:
    → Verificar services.msc: "Apollo Centinela Agent" debe estar RUNNING
    → Revisar C:\ProgramData\ApolloSupport\service.log
    → Verificar que base_ws_url en centinela_config.json apunta al servidor correcto

  "Acceso denegado" al reinstalar agente:
    → Ya corregido en ApolloSetup_v3.0.0.exe (PrepareToInstall mata procesos antes)
